K&R Exercises

Work through every exercise in The C Programming Language without leaving your browser. Write your solution, submit it, and it's compiled and run against a set of tests, with any difference from the expected output highlighted line by line. When you're stuck, compare with a reference solution.

Why K&R

Written by Brian Kernighan and Dennis Ritchie, the creator of C, The C Programming Language is one of the most celebrated programming books ever written. It's short and precise, and it's known for its exercises: they build directly on the text, leave the edge cases to you, and are famously challenging. Solving them is one of the best ways to really learn C.

How it works

  • Pick an exercise and write your solution in the editor.
  • Each submission is compiled with gcc -Wall -std=c17 -fsanitize=address -o main main.c -lm and run against tests that supply input, command-line arguments and files. The sanitizer stops a run that reads or writes outside an array.
  • See which tests pass, exactly where your output differs, and your submission history.

Questions

We added tests to that exercise. An exercise only counts as passing once your code has run against every one of its tests, and it hasn't run against the new ones yet. Your code is still saved: open the exercise and submit it again to see whether it passes them too.

Nothing is saved on our side, though: sign in, with Google or an email link, to keep your code, your results, your progress in the sidebar and your submission history, on any device.

Each test gives your program a short time to finish, far more than a correct solution needs. A program that hits the limit is almost always stuck in a loop that never ends. A common cause is a loop that waits for a particular character, such as a newline, and never checks for EOF: when the input runs out first, it keeps going forever.

Architecture

  • Angular with server-side rendering and an Express API, hosted on Firebase App Hosting
  • Every submission runs in its own isolated Vercel Sandbox microVM with no network access and strict time limits
  • Firebase Authentication with Google or passwordless email link, exchanged for an httpOnly session cookie so pages render already signed in
  • Firestore for your code, test results and submission history
  • Upstash Redis for rate limiting
  • Plausible for cookieless visit counts
  • Firebase App Check with reCAPTCHA to protect the API
  • NgRx for state, CodeMirror for the editor and NG-Zorro for UI components
